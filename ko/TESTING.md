테스트는 로컬 JavaScript 실행 환경에서 수행했습니다. 브라우저 DOM을 사용하는 실제 확장 E2E 테스트와 제공자 실계정 테스트를 대체하지 않습니다. 통합 테스트의 계정·토큰·모델·추론 응답은 테스트용 모의 값이며 실제 사용자 정보가 아닙니다.

주요 검증 내용:

- PKCE 표준 벡터, 콜백의 정확한 주소·state, 서명·issuer·audience·만료·nonce
- 잘못된 번역 구조, 누락·중복 ID, 불완전하거나 실패한 스트림 거부
- 페이지·블록 복원, 한 배치 중 일부 블록 복원, 복원 후 늦은 결과 차단
- 재번역 시 원문 사용, 사이트 변경·노드 교체·DOM 재구성에 대한 보존
- 클라우드 동시 요청 기본 16개·최대 64개, 브라우저 내장 방식의 순차 처리와 취소
- 콘텐츠 스크립트의 계정 관리 접근 차단, 토큰 비공개
- 문서 간 작업 ID 재사용 거부, 작업 시작 시 설정 고정
- 로그아웃·제외 사이트·명시적 원문 복원의 요청 처리

## 브라우저 검증 절차

1. `extension/`을 Chrome 개발자 모드에서 로드합니다.
2. 팝업에서 계정 로그인을 실행하고 기존 세션의 계정이 사용되는지 확인합니다. 비밀번호나 토큰을 로그·문서에 복사하지 않습니다.
3. 실제 모델 목록을 조회하고 모델을 선택합니다. 짧은 공개 텍스트로 실제 번역을 확인합니다.
4. `node scripts/serve-fixture.mjs`를 실행한 뒤 `http://localhost:3185/fixture.html`을 엽니다. 이 서버는 개발용 fixture 전용이며 확장의 설치·인증·일반 사용에 필요하지 않습니다.
5. 페이지 번역 → 블록 하나 복원 → 전체 원문 복원을 확인합니다. 링크 클릭 횟수와 강조·표 구조가 보존되어야 합니다.
6. 개별 블록 두 개를 번역한 후 페이지 원문 복원으로 두 블록을 모두 복원합니다.
7. 페이지 번역 도중 원문 복원을 누르고, 이후 늦게 도착한 응답이 텍스트를 바꾸지 않는지 확인합니다.
8. 번역된 문단에서 사이트 텍스트 변경 버튼을 누른 후 원문 복원을 실행합니다. 사이트의 새로운 텍스트는 유지되어야 합니다.
9. 폼·편집기·코드·숨겨진 요소가 번역되지 않는지 확인합니다.
10. Alt+Shift+T, Alt+Shift 유지·클릭, 설정한 대체 단축키와 선택 취소를 확인합니다.
11. 새로고침, SPA 이동, 프레임, 열린 Shadow DOM, 로그인 해제, 오프라인 복원을 확인합니다.
12. 팝업과 설정 화면을 밝게·어둡게, 100·125·150·200% 배율로 검토합니다.
13. 동등한 조건으로 Edge·Brave를 검증하고 실제 지원 결과를 기록합니다.

영문 UI는 모의 API를 사용하는 브라우저 미리보기에서 확인했습니다. 실제 확장 설치, offscreen 문서에서의 모델 생성, 다운로드 및 추론은 아직 검증하지 못했습니다. 확장을 다시 로드한 후 준비 완료 안내가 나타나면 탭을 닫고 번역을 확인하세요. 브라우저 재시작, 새 언어 팩, 명시적 중지와 연결 해제, 백그라운드 실행이 막힌 환경도 확인해야 합니다. 자세한 절차는 루트 TESTING.md를 참고하세요.

## 팝업 원본 언어 및 준비한 언어 쌍

전용 13개 테스트는 페이지 언어 감지, 미지원·감지 실패 시 자동 선택, 명시적으로 선택한 자동 유지, 클라우드 직접 입력, 네이티브 지원 언어 제한, 동일 언어 처리, 누락된 팩 설치 탭 열기, 언어 쌍 상태·목록 제거, 탭·문서별 선택과 캐시 구분, 작업 시작 시 언어 고정, 메시지 권한·이전 문서 거부, 새로고침·탐색 초기화, 명시한 원본 언어 우선 처리를 검증합니다. 추가 네이티브 통합 테스트는 재감지 없이 명시 언어를 전달하고 정확한 언어 쌍으로 설치 탭을 재사용하거나 다시 여는 동작을 검증합니다. Translator 테스트는 동일 언어만 지원하는 API의 잘못된 활성화와 상태 확인 중 수동 설치 언어 변경을 검증합니다.

모의 API를 사용한 영문 팝업·설정 미리보기에서 감지된 영어, 네이티브 프랑스어 선택, 클라우드 자동·직접 입력, 언어 쌍 목록 제거를 확인했습니다. 실제 팩 다운로드와 브라우저 파일 삭제는 수행하지 않았습니다. Translator API는 전체 설치 목록이나 삭제 기능을 제공하지 않으므로 이 확장에서 준비한 언어 쌍을 표시하며, 목록에서 제거해도 브라우저의 팩 파일은 남습니다.

수동 확인: 실제 지원 브라우저에서 페이지 감지와 원본 언어 변경·자동 선택 후 페이지·블록·선택 텍스트 번역을 확인합니다. 원본 변경 시 캐시 구분, 새로고침·탐색 후 재감지, 클라우드 직접 입력 및 두 네이티브 방식의 지원 언어 제한을 한·영 UI에서 확인합니다. 미준비 조합을 요청해 자동으로 열린 탭에서 준비한 뒤 재시도하고, 설정에 해당 언어 쌍이 추가되며 상태 새로고침과 목록 제거가 동작하는지 확인합니다.

두 스위치는 새 설치와 기존 설정 모두 기본적으로 꺼집니다. On-Device AI 테스트 9개를 추가해 설정 검증·이전 설정 가져오기, 두 스위치의 모든 조합과 비활성 상태의 API 검사 생략, 로그인 전 설정, 한·영 성능 경고, 미지원 브라우저 숨김, Translator API 유지, 다시 켤 때 지원 언어 갱신, 열린 화면 간 설정 동기화, 워커·준비 페이지 차단과 실행 중 해제를 검증했습니다. 숨겨진 실행 테스트 1개를 추가해 두 스위치 각각으로 진행 중 추론을 취소하고 준비 상태를 해제하는 동작을 확인했습니다.

모의 API로 영문 설정 화면의 마지막 항목, 상위 스위치와 개별 스위치의 순차 표시, 성능 경고, 활성화 후 연결 방식 표시를 확인했습니다. 실제 모델 성능 측정은 수행하지 않았습니다. 실제 브라우저에서는 업그레이드 후 기본 비활성 상태, 준비·번역 중 각 스위치 해제, 팝업·준비 탭 동기화, Translator API의 독립적인 사용을 확인해야 합니다.
